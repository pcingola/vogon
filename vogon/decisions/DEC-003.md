# DEC-003: The test manager produces the traceability report where one exists

Where a test manager is configured, it produces the traceability report, and
VOGON builds the matrix only where none is configured.

**Context.** A validation package needs a traceability matrix. The matrix can
be computed from the test markers and a JUnit XML file, and a test manager
such as Xray computes it from the results uploaded to it.

**Options.**

VOGON builds the matrix in every project. One format everywhere, and VOGON
code becomes the source of validation evidence in projects that already have a
validated tool for it.

The test manager produces the report, and VOGON builds the matrix only where
no test manager exists. Two formats of matrix exist across projects.

**Decision.** Where a test manager is configured, VOGON uploads the JUnit XML
unchanged and the test manager produces the report. Where none is configured,
`vogon trace` joins the markers and results of one commit into the matrix.

**Consequences.** A project with a test manager gets its report from a tool
that has its own validation. A project without one gets the matrix from
`vogon trace`, which is deterministic code. The matrix never comes from a
model. Projects with and without a test manager file matrices in different
formats. A requirement with no item in the test manager is missing from its
report.

**Example.** A project with a test manager uploads the results of the release
commit to it and files the report it produces. A project without a test
manager files the output of `vogon trace`, which lists each requirement, its
tests, their results and every requirement with no test.
