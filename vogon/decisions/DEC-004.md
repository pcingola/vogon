# DEC-004 — Version 0.1 targets one stack and abstracts over nothing

**Context.** Trackers, test managers and coding agents all differ. Writing
against an interface from the start would let a second one be added later.

**Options.**

Define a tracker interface and a test-manager interface now, with one
implementation behind each. Portable in principle, and in practice shaped by
the only implementation that exists, so the second one does not fit it anyway.

Write directly against one stack and extract an interface when a second is
needed.

**Decision.** Version 0.1 assumes Python for the host project and for VOGON,
GitHub for the repository, Jira for requirements under approval, Xray for
tests and coverage, and Claude Code as the coding agent that drafts records and
writes tests. Nothing is abstracted over.

**Consequences.** The code is smaller and every path is exercised. Supporting a
second tracker means a refactor rather than a plug-in, which is the cost this
decision accepts. The assumption set is stated in the documentation so the
coupling is visible rather than discovered.

**Example.** A host project on GitLab with a different test manager cannot install
version 0.1. There is no adapter to write, because there is no interface to
write one against.
