# DEC-026 — Change control after go-live stays with the host project's own procedure

**Context.** Once a validated system is live, every change to it, each release
after the first included, needs a change record: an impact assessment naming
the requirements, tests and documents the change touches and what has to be
re-tested, approved before the change ships. The shape of that record is set
by each company's change control procedure. VOGON's skills already carry each
new or changed requirement through the steps of the GxP process and produce
the validation documents for each release.

**Options.**

Draft the change record with a skill. Without a company's procedure to follow,
its format would be guessed, and the first real procedure would replace it.

Leave the change record to the host project's procedure, and state which part
VOGON covers.

**Decision.** VOGON produces no change record and no impact assessment, and
supersedes `DEC-017` with the same scope stated against the current skills. A
change to a live system is recorded and approved in the host project's own
change control system. The requirements, test cases, code and release
documents of that change go through the same steps and skills as the first
release. What VOGON reads for its own work, such as which requirements a pull
request changes and which tests name them, is material for the person
writing the change record, and is not the record.

**Consequences.** A project with a live system uses VOGON for everything in a
change except the change record and its approval. Each release package covers
the requirements in that release, and the link from the package to the change
record is made by the person who files it. Adding change control later is a
skill reading the same requirement links, tracker issues and test markers the
other skills use.

**Example.** A defect is found in a live label printing system. The team opens
a change record in its change control system and gets it approved. A
developer runs `vogon:implement` on the corrected requirement; the Product
Owner approves the changed text and the Test Lead the changed test cases.
`vogon:release` produces the package for the release commit, and the
developer cites the change record when filing it.
