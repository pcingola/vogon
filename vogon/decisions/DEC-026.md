# DEC-026: Change control after go-live stays with the host project's own procedure

VOGON produces no change record and no impact assessment for a change to a live
system.

**Context.** After a validated system goes live, each change to it needs a
change record, approved before the change ships. The change record holds an
impact assessment: the requirements, tests and documents the change affects,
and what is re-tested. Each company's change control procedure sets its format.

**Options.**

A skill drafts the change record. With no company procedure to follow, its
format is a guess, and the first real procedure replaces it.

The host project's procedure covers the change record, and VOGON covers the
rest of the change. The release package and the change record are linked by
hand.

**Decision.** A change to a live system is recorded and approved in the host
project's own change control system. Its requirements, tests, code and release
documents go through the same skills as the first release.

**Consequences.** The person who files a release package links it to the change
record by hand.

**Example.** A team finds a defect in a live label printing system and gets a
change record approved in its change control system. A developer runs
`vogon:implement` on the corrected requirement, and `vogon:release` produces
the package for the release commit. The developer cites the change record when
filing the package.
