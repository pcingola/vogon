# DEC-025 — External systems are named by role, and the server for each role is chosen at setup with no default

**Context.** VOGON reaches systems it does not own: the tracker, the test
manager, the repository host, the document system. Which product fills each
role is decided by the company's IT and quality organisation, and a regulated
company usually mandates both the product and the access path to it. A
company that runs Jira may forbid the vendor's MCP server and require its own.
`DEC-011` settled that the role is named and the product is configuration,
and added that VOGON ships a default server for a role nothing fills. A
developer often has more than one server connected to Claude Code, including
ones the company does not permit for controlled records.

**Options.**

Name the products throughout, in records, documentation and generated text.
Precise while the assumption holds, and wrong in every host project that made a
different choice.

Name the role, make the product and server configuration, and ship a default
server per role. Setup needs no answer, and a host project with the vendor's server
connected beside its own writes records to whichever one the default names.

Name the role, make the product and server configuration, and set the server
for each role during setup from the servers connected, with the person
choosing where several could fill it.

**Decision.** Records, documentation and generated text name the role. What
VOGON states for each role is the operations it needs: for the tracker, read
an issue and its approval state, create an issue, link two issues; for the
test manager, create or find a test issue, link it to a requirement issue,
read its review state, import a result keyed to a build. The product, and the
MCP server through which it is reached, are configuration. The server for a
role has no default. It is set during setup from the servers connected to
Claude Code: where one provides the role's operations it is used, and where
several do, the person chooses. A role that no connected server fills stays
unconfigured. This replaces `DEC-011`.

**Consequences.** `DEC-004` continues to hold: version 0.1 is written and
tested against one set of products and abstracts over nothing in code. Setup
asks a question wherever two servers could fill a role, which is the cost of
never sending a record to a system nobody chose. A step or check that needs a
role with no server reports the role as not configured. A configured server
that lacks a required operation is reported at setup rather than at first use
(`REQ-CLI-4`).

**Example.** A developer has the vendor's Jira server and the company's own
Jira server connected. Setup finds that both provide the tracker's operations
and asks which one fills the tracker. The person names the company's server,
and no record is ever written through the vendor's.
