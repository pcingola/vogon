# DEC-006: The trace runs from the test to the requirement

Each test names the requirements it verifies in a marker, and the requirement
does not list its tests.

**Context.** A link from each requirement to the tests that verify it has to
stay correct while the code changes.

**Options.**

A list of test names in each requirement. Readable in the record, and wrong
after a test is renamed, with nothing to detect it.

Requirement ids in comments in the implementation code. Common practice, and
nothing detects a comment that is wrong.

A marker on the test function naming the requirement ids. The record does not
show its tests.

**Decision.** The test carries the marker `@pytest.mark.req`. Whoever changes
the test changes the marker in the same edit. Implementation code names no
requirement id.

**Consequences.** The person who has the reason to edit the link edits it, and
a deleted test removes its link. The matrix lists every requirement with no
test, and `vogon:release` reports each marker that names an unknown
requirement. To find the tests of a requirement, a reader reads
the matrix, not the record.

**Example.** A refactor deletes a test and its marker in the same commit. The
next matrix lists the requirement it verified as having no test, and nobody
edited a record.
