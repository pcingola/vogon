# DEC-018 — Each approval is given by a role, and who holds the role is configuration

**Context.** A host project developed under GxP passes through several approvals:
the requirements are approved before the work is planned, the test cases
before their results are used, each change to the code before it merges, and the
validation package before release. Each company's procedure says which role
gives each approval, in which system, and a validation plan names the person
who holds each role. The person is often not known when the host project starts,
and changes during it.

**Options.**

Name the people in the records and the generated documents. Wrong as soon as
someone changes job, and it puts personal names into every file that mentions
an approval.

Fix the roles in VOGON. Every company whose procedure assigns an approval
differently has to change VOGON.

Name the role in records and documents, and configure both the role each
approval is given by and the people who hold each role.

**Decision.** Records, instructions and generated documents name the role
that gives an approval, never a person. The host project's `vogon.yaml`
states, for each approval, the roles that give it and the system it is given
in, and, for each role, the people who hold it. A role may be configured with
no holder while the host project's procedure has not named one. VOGON ships a
default assignment: the Product Owner approves the requirements in the
tracker, the Test Lead approves the test cases in the test manager, an
engineer other than the author approves a change on the repository host, and
the validation package is signed in the document system by the roles the
validation plan names.

**Consequences.** A company's procedure is expressed in one reviewed file, and
a new holder of a role is a one-line change. VOGON can check an approval
against the configuration: whether the person who gave it holds the role, and
whether a role needed by a step has any holder. VOGON still never gives an
approval itself (`CON-001`), and the configuration does not relax the rule
that an author does not approve their own work (`CON-002`).

**Example.** The validation plan says the package is signed by the System
Owner and the IT Quality Manager, and the IT Quality Manager has not yet been
appointed. `vogon.yaml` lists both roles for sign-off and names a holder for
the first only. VOGON reports the unfilled role before the package is
assembled, and the configuration gains the name when the procedure confirms it.
