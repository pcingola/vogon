# DEC-008 — One writing standard covers documents, records and generated text

**Context.** Four kinds of text come out of the VOGON project: the developer
documentation, VOGON's own records, the text VOGON writes into a tracker, and
the drafting instructions it installs into a host project. Each could have its
own conventions. The product also has a satirical public voice.

**Options.**

A separate convention per surface. Each fits its context, and a record drafted
by an agent reads differently from one written by a person, so the two cannot
be reviewed by the same eye.

The satirical voice applied to generated content as well, which the brand
guide originally stated. It is the wrong voice for a record someone is
answerable for, and it obstructs the reader.

One standard for every surface that a reader reads to find out what to build.

**Decision.** One writing standard, published in the developer documentation
and installed into the host project alongside the drafting instructions. It
covers everything the VOGON project produces except the marketing page: this
documentation, the README, CLI output, every record, every tracker field VOGON
writes, and everything a coding agent drafts under those instructions. The
satirical voice is limited to the marketing page.

**Consequences.** A generated record and a hand-written one are
indistinguishable in style, so review is about content. The standard has to be
installed into the host project, which is one more file VOGON writes there.
Most of the standard is not mechanically checkable, so a checker enforces a
narrow subset and the rest is a review judgement.

**Example.** A requirement drafted by the agent from a meeting transcript and one
written by hand read the same way. A reviewer cannot tell which is which, so
the review is about what the record says.
