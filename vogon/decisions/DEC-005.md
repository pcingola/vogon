# DEC-005: VOGON's Python code does not call a language model

The Python code in `src/vogon` calls no language model, and Claude Code running
the skills does all model work.

**Context.** Drafting records from a meeting summary can run in a VOGON command
that calls a model, or in the Claude Code session that runs the skills.

**Options.**

A script that calls a model. One command for the user, model credentials in the
tool, and output that differs between runs of the same command.

Skills that Claude Code runs, with scripts only for work that must give the
same result every time. The user needs Claude Code to get any drafting.

**Decision.** The Python code in `src/vogon` calls no language model API and
depends on no model client library. Drafting, reviewing and sub-agents run in
Claude Code. The scripts `vogon id`, `vogon approve` and `vogon trace` do the
work that must be deterministic.

**Consequences.** Evidence such as the traceability matrix comes from a script
or a test manager, never from a model. A project that wants drafting without a
person present has to run Claude Code itself.

**Example.** `vogon trace` runs offline with no model credentials and gives the
same matrix for the same JUnit XML. Drafting a requirement from a summary is
done by `vogon:requirements` in Claude Code.
