# DEC-021 — One skill holds the shared rules, with a reference file per pipeline step

**Context.** The instructions VOGON ships cover every step of the pipeline,
from filing a transcript to filing the evidence. Every step shares some rules:
the order of the pipeline, the actions VOGON never takes, such as moving an
issue into an approved state, and how subagents are used. Each step also has
rules of its own. Claude Code loads a skill's `SKILL.md` when the skill is
used, and reads a file the skill points to only when the step needs it.

**Options.**

A skill per step. Each skill loads only what its step needs, and each repeats
the shared rules. A change to a shared rule has to be made in every copy, and
a copy that was missed contradicts the others without anything reporting it.

One skill with every rule in `SKILL.md`. Nothing is repeated, and every step
loads the rules of every other step, so the rules for the step in hand are a
small part of a long file.

One skill, `vogon`, whose `SKILL.md` holds the shared rules and a table from
each step to a reference file holding that step's rules.

**Decision.** One skill, `vogon`. `SKILL.md` holds the pipeline, the actions
VOGON never takes, the rules for subagents, the rule that a role is reached
only through its configured server, and the table from step to reference
file. It is at most 150 lines. Each reference file is at most 120 lines and is
a checklist of rules the step's output meets or fails, so a checker can apply
it item by item. The actions VOGON never takes are stated in `SKILL.md` only.

**Consequences.** A shared rule is written once. A step loads `SKILL.md` and
its own reference file. The line limits force a rule to be stated briefly or
moved to the documentation, and a step whose rules do not fit in 120 lines
has to be split. A reference file used by several steps, such as the one for
the tracker, holds the rules of each of them.

**Example.** The rule that no transition into an approved state is performed
changes wording. The change is made in `SKILL.md`, and every step reads the
new wording, because no reference file holds a copy.
