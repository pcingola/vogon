# DEC-027 — The validation plan is drafted at setup, and the URS and validation summary report at release

**Context.** GAMP 5 expects a validated system to have a validation plan,
approved by the System Owner and the Quality Manager before the validation
work it governs, and a validation summary report at release that states,
against the plan, what was done, what deviated and whether the system is fit
for use. It also expects the approved user requirements as a controlled
document, the URS. The steps of the GxP process named none of the three.

**Options.**

Leave all three to the project, as documents written outside VOGON. Every
fact in them is already held by VOGON's configuration, records and release
documents, so the project would write by hand what VOGON could draft and
check.

Draft them with VOGON: the plan once per project, revised when its content
changes, and the URS and summary report with each release package.

**Decision.** `vogon:setup` drafts the validation plan after writing
`vogon.yaml`: the system and its GAMP category, the roles and their holders,
the systems used, the documents each release produces, how risk sets the
testing, and what must hold for release. A checker checks it, and it is kept
in `vogon/documents/validation_plan.md` and approved by the System Owner and
the Quality Manager: by pull request review in the prototype, in the document
system in a deployment. A change to its content goes the same way. At release,
`vogon:release` compiles the URS from the approved requirements in the release,
and drafts the validation summary report against the plan. Both are signed
with the package.

**Consequences.** Setup gains an approval by the System Owner and the Quality
Manager, and validation results do not count as evidence until the plan is
approved. The plan states the risk approach the architecture already uses, so
a project whose procedure demands a different approach changes the plan and
the skills follow it. The URS adds no new mechanism: it is the set of
approved requirements, compiled the same way as the risk assessment.

**Example.** A project sets up VOGON. Setup writes `vogon.yaml` and drafts a
plan naming the system as GAMP category 5, listing the role holders and the
release documents. The System Owner and the Quality Manager approve it. At the
first release, the package holds the URS, the risk assessment, the test
specification, the design specification, the test report and the summary
report, which states that two test cases failed, were fixed and passed on the
release commit.
