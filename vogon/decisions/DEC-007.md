# DEC-007 — The four record types are fixed in version 0.1

**Context.** Host projects have statements that do not fit requirement, fact,
constraint or decision — a glossary term, a risk, an assumption. They could be
accommodated by letting the host project define types.

**Options.**

A configurable type registry. Fits every host project, and gives each host project a
different schema, so a check written against one does not hold for another and
the id grammar stops being a single pattern.

Four fixed types, extended by `tags` where a host project needs a finer cut.

**Decision.** Requirement, domain fact, constraint and decision, fixed. A
host project that needs a further distinction uses `tags`.

**Consequences.** Every host project's records are checked by the same rules and
read the same way. A host project with a genuinely fifth kind of statement has to
file it as one of the four or keep it outside `vogon/`. Adding a type later is a
schema change with a migration, which is the cost of not guessing now.

**Example.** A host project that wants to distinguish a regulatory commitment from an
internal rule files both as constraints and separates them with a tag. It does
not add a fifth type.
