# DEC-015 — A record is registered in every system that holds it, and one of them governs

**Context.** `tracked_as` held a single key, on the assumption that one
external system holds a record. Host projects have always run more than one system
that tracks work, and a company's quality organisation adds its own. A record
can be an issue in the tracker, an entry in the test manager, and a row in
something else at the same time.

**Options.**

Keep one key and treat every other registration as outside VOGON's view. The
record then cannot reach the other systems, and a host project with a mandated
second system has nowhere to put its key.

Hold every key, and name which system's approval counts.

**Decision.** `tracked_as` is a map from the role of each external system to
the key the record has in it, with one entry naming the role that governs.
Approval state is read from the governing system and from no other. VOGON
checks that every key under every role still resolves. It does not compare
what two external systems say about the same record.

**Consequences.** A reader reaches every registration from the record. There
is still one answer to whether a record is approved, which `CON-003`
requires. Where two systems hold the same statement and disagree, VOGON
reports neither as wrong, because the host project owns that disagreement and
VOGON has no basis to settle it.

**Example.** A record carries a tracker key and a test-manager key, with the
tracker as governing. A run reads approval from the tracker, and reports the
record if either key stops resolving.
