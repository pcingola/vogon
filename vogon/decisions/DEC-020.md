# DEC-020 — VOGON is distributed as a Claude Code plugin

**Context.** VOGON's skills, subagents and hooks have to reach Claude Code in
the host project, and the scripts they call have to run there. The scripts
need nothing beyond `uv`, so they need no package of their own.

**Options.**

A Python package that copies the skills, subagents and hooks into the host
project's `.claude/`. That is two install paths and two version numbers, and
every upgrade is a reinstall, a re-copy and a reviewed diff.

A Claude Code plugin holding the skills, subagents, hooks and scripts.

The plugin, plus a copy of the skill text committed in the host project. That
records the skill text at each commit of the host project, which no audit asks
for.

**Decision.** VOGON is a Claude Code plugin, installed from a marketplace in
the VOGON repository, with the scripts inside the plugin and run with `uv`.
Nothing from the plugin is copied into the host project.

**Consequences.** Installing is `/plugin marketplace add` followed by
`/plugin install`, and upgrading is a plugin update. The host project's
repository does not hold the skill text that produced its records. That is
accepted, because what a validation record rests on is a person's approval of
each document, and the agent's output is not evidence whatever produced it
(`FACT-005`).

**Example.** A developer installs the plugin and asks Claude Code to set up
VOGON. `vogon/` and `vogon.yaml` appear in the host project, and nothing under
`.claude/` except the settings entry that enables the plugin.
