# DEC-019 — A second agent checks the test cases against the requirements before a person approves them

**Context.** A requirement is verified when its tests exercise what the
requirement states: every clause of the acceptance block, with the expected
values the block gives. The marker checks in `TRC` establish that a test names
the requirement, and nothing about what the test asserts. A test can name the
right requirement and verify something else, or verify one clause of three.
The Test Lead approving the test cases reads them, and a set of generated tests
is large enough that a mismatch passes a reader.

**Options.**

Rely on the Test Lead's review alone. Nothing prepares the review, and
thoroughness varies with the size of the set.

Measure it mechanically, with code coverage or a count of markers. Code
coverage measures which lines of the implementation ran, which is a property
of the code and says nothing about the requirement. A marker count says a test
exists.

Have a second agent, which did not write the tests and cannot read the
implementation, compare each requirement with the tests that name it and
report every mismatch, and give that report to the Test Lead.

**Decision.** After the test cases are written and before they are
registered for approval, a subagent reads each requirement, its acceptance
block and the tests whose markers name it, and reports: each clause of the
acceptance block that no test exercises, each expected value in a test that
differs from the acceptance block, and each assertion that does not follow
from the requirement. It has no read access to the implementation, so the
comparison is between the requirement and the tests. The report goes to the
Test Lead with the test cases.

**Consequences.** Every requirement verified by test is checked for whether
its tests cover what it states, independent of its risk level. The check is a
judgement made by a language model, so its report informs the Test Lead's
approval and does not replace it, and it is not validation evidence
(`FACT-005`). A test written against a clause the agent missed still reaches
the Test Lead unflagged.

**Example.** A requirement's acceptance block states the result for a value
below the range, inside it and above it. The tests name the requirement and
exercise the value inside the range only. The report lists the two missing
clauses against the requirement, and the Test Lead returns the test cases
before approving them.
