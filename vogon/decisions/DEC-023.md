# DEC-023 — Drafted documents are kept in vogon/documents and approved in the document system

**Context.** VOGON drafts the documents a validation package holds: the risk
assessment, the test specification, the design specification and the test
report. Each is approved by a person in the document system. The draft needs
a place in the host project where it is written, reviewed and compared with
the records. `vogon/out/` holds generated output that a script may overwrite
at any time.

**Options.**

Write the drafts to `vogon/out/`. Nothing new in the layout, and a draft that
a person has edited is overwritten by the next run, or else `vogon/out/`
stops meaning generated-only.

Write the drafts only to the document system. One copy, and the draft cannot
be reviewed in a pull request, and the scripts cannot compare it with the
records, which is how a risk assessment that no longer matches its records is
found (`REQ-GEN-9`).

Write the drafts to a directory of their own in `vogon/`, and file each into
the document system for approval.

**Decision.** Drafted documents live in `vogon/documents/`. Each is filed into
the document system and approved there, by the roles `vogon.yaml` assigns to
that approval. `vogon/out/` stays generated-only. `vogon.yaml` gains two
approvals given in the document system: `risk_assessment`, whose default
roles are the System Owner and the IT Quality Manager, and
`test_specification`, whose default role is the Test Lead. The test issues
stay approved in the test manager under `test_cases`.

**Consequences.** A draft is reviewed in the pull request that changes it, and
the scripts compare it with the records. The copy in the repository is not
controlled; the approved copy is the one in the document system, and a draft
edited after filing has to be filed again and approved again. The risk
assessment and the test specification each have an approval of their own,
which the default assignment in `DEC-018` did not list.

**Example.** The risk assessment is drafted to
`vogon/documents/risk_assessment.md`, reviewed in a pull request, filed in the
document system and approved there by the System Owner and the IT Quality
Manager. A later run of `vogon index` rewrites `vogon/out/` and leaves the
risk assessment untouched.
