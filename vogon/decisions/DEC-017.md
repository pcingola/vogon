# DEC-017 — Change control is not in version 0.1

**Context.** A validated system that is live changes only through change
control: an assessment naming what the change affects, which requirements and
tests it touches and what has to be re-tested, approved by a board before the
change ships. VOGON's pipeline runs from the source material to the release
evidence and stops there.

**Options.**

Cover it now, with a skill that drafts the impact assessment from the records
and the markers. The shape of that assessment is set by each company's own
change control procedure, and we hold none, so the document would be guessed
and the first real procedure would replace it.

Leave it out and say so, so that nobody reads the pipeline as covering a step
it does not.

**Decision.** Version 0.1 produces no impact assessment and no change control
package. A host project running a live system performs change control with its
existing procedure. What VOGON already reports — which records changed, which
requirements they touch, which tests name those requirements — is material a
person uses when writing that assessment, and is not the assessment.

**Consequences.** A company installing VOGON on a system already in production
gets less from it than one building a new system, and has to be told which part
VOGON does not cover. Nothing is built now to anticipate the assessment's
shape. Adding it later is a skill over output that already exists rather than
new machinery, because the links a change assessment needs are the same links
the record checks and the markers already maintain.

**Example.** A defect is found in a live system. The team changes the record,
plans the change, writes the test and pushes to the tracker with VOGON, and
writes the impact assessment in its own change control system. VOGON reports
which requirements the changed records touch and which tests name them, and
takes the change no further.
