# DEC-006 — The trace runs from the test to the requirement

**Context.** Something has to connect a requirement to the test that verifies
it, and it has to stay correct while the code changes.

**Options.**

A list of test names held against each requirement. Readable in the record, and
stale the moment a test is renamed, with nothing to detect it.

Requirement ids in comments in the implementation source. Widely done, drifts
silently, and nothing checks it.

A marker on the test function naming the requirement ids it verifies.

**Decision.** The test carries the marker. Whoever changes the test changes the
marker, in the same commit. Requirement ids do not appear in implementation
source as comments.

**Consequences.** The trace is edited by the person with the reason to edit it,
and a test deleted takes its trace with it. The link can be checked
mechanically against the records, so a marker naming a requirement that does
not exist fails the build. The record does not list its tests, so answering
"what verifies this" means reading the markers rather than the record.
