# DEC-009 — Held documents go in one flat dated directory

**Context.** A record cites the documents it came from, and the citation has
to be checkable later. That means holding a copy of each document in the
repository, and deciding what to call it and where to put it.

**Options.**

A directory per kind: transcripts, procedures, standards, decks. Browsable,
and it forces a classification at filing time that is often wrong and always
arbitrary. A document that is a deck summarising a procedure has two homes and
gets one at random, so citations point at whichever the filer chose.

A directory per record or per module. Keeps a record's evidence next to it,
and duplicates every document cited twice.

One flat directory, files named by the document's own date and a slug, with
the kind in frontmatter.

**Decision.** `gxp/sources/`, flat, `YYYY-MM-DD_slug.ext`. The date is the
document's own, not the filing date. A document that is not text is held twice,
as the original and as a markdown conversion beside it with the same stem.
Records cite the markdown. A held document is never edited after filing.

**Consequences.** The directory sorts chronologically, which is how people look
for a meeting. Nothing has to be classified to be filed, and `kind` and
`authority` in frontmatter carry what a directory tree would have encoded
badly. A large project accumulates a long directory listing, which is what the
generated index is for. Holding originals puts binaries in git, which is
accepted: they are small relative to the repository and they are the evidence.

**Example.** A slide deck presented on 3 March 2026 is filed as
`2026-03-03_validation-approach.pptx` with `2026-03-03_validation-approach.md`
beside it. Records cite the markdown. Neither file is edited again.
