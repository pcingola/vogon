# DEC-007 — The four record types are fixed in version 0.1

**Context.** Projects have statements that do not fit requirement, fact,
constraint or decision — a glossary term, a risk, an assumption. They could be
accommodated by letting the host project define types.

**Options.**

A configurable type registry. Fits every project, and gives each project a
different schema, so a check written against one does not hold for another and
the id grammar stops being a single pattern.

Four fixed types, extended by `tags` where a project needs a finer cut.

**Decision.** Requirement, domain fact, constraint and decision, fixed. A
project that needs a further distinction uses `tags`.

**Consequences.** Every project's records are checked by the same rules and
read the same way. A project with a genuinely fifth kind of statement has to
file it as one of the four or keep it outside `gxp/`. Adding a type later is a
schema change with a migration, which is the cost of not guessing now.
