# DEC-003 — Coverage and traceability reporting is left to Xray

**Context.** A validation package needs a requirements traceability matrix and
a coverage report. Both can be computed from the records and the test markers
in the repository, and both are produced by Xray from the issues and imported
results.

**Options.**

Generate the matrix locally. Works offline, needs no tracker, and produces
output tied to the repository rather than to what was approved. It also makes
VOGON a producer of validation evidence, which brings its own fitness-for-use
obligation.

Let Xray report, and maintain the links it reports on.

**Decision.** VOGON does not generate a coverage or traceability report. It
maintains the link between the Xray test issue and the requirement issue,
imports results against those test issues, and leaves the reporting to Xray.

**Consequences.** The report comes from a commercial tool with its own
validation, which is stronger evidence than output from code we wrote, and
VOGON stays out of the category of tools whose output is evidence. The report
can only cover issues that exist, so a record never pushed is invisible in it;
the local checks in `TRC` exist to catch exactly that. A project without Xray
gets no matrix from VOGON, which is a limitation version 0.1 accepts.
